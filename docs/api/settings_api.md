# Settings API

All endpoints are called via **POST** with a JSON body. Every request must include the `#request` field set to `"Settings/<endpoint_name>"`.

**Standard Response Format:**
```json
{
    "rc": 0,
    "message": "success"
}
```

A non-zero `rc` indicates an error. Additional data fields are merged into this base structure when applicable.

**Authentication:** All endpoints require a `#token` field in the request body. Unless noted otherwise, only Admin-type users may call these endpoints.

---

## Concepts

### Type Management (Service, Task, Asset, Post Order Section)

The Settings module exposes CRUD operations for several managed type lists used throughout the platform. Each type is identified by a unique `type_id` generated by the system on creation. Types are simple named entries that appear in dropdown lists, filters, and categorization throughout the consumer apps and management portal.

- **Service/Incident Types** — categories presented to residents and officers when opening or viewing calls (e.g., Fire, Medical, Police).
- **Task Types** — categories for maintenance reports created by officers.
- **Asset Types** — categories for physical assets plotted on community maps.
- **Post Order Section Types** — predefined section categories available when composing post orders, each with a client-visibility flag.

### Key-Value Configuration Settings

GPS, Notification, POI, and Working Hours settings are global configurations stored as key-value pairs. Each settings group has system-defined defaults. When a setting has never been explicitly changed, the default value is returned. Only provided fields are updated; omitted fields retain their current value.

## Endpoints — Service Types

### POST Settings/get_service_types
*Admin, Officer, or Resident.* Retrieves all service/incident types configured in the system.

- **API Parameters:**
    | Parameter | Type | Required | Description |
    |-----------|------|----------|-------------|
    | `#token` | string | Yes | A valid session token. |

- **Return Values:**
    ```json
    {
        "rc": 0,
        "message": "success",
        "items": [
            {
                "type_id": "abc123",
                "name": "Fire"
            },
            {
                "type_id": "def456",
                "name": "Medical"
            }
        ]
    }
    ```

    The `items` array contains all active service/incident types. Each entry includes its unique `type_id` and display `name`.

- **Error Cases:**
    | rc | Message | Scenario |
    |----|---------|----------|
    | 201 | invalid user token | Invalid or expired token. |

- **Usage & Flows:**
    Called by the consumer app when displaying the service type selection during call creation (SDS 2.4.1.1). Also used in the management portal's Settings page (SDS 5.4.1) to display the current list for admin management.

---

### POST Settings/add_service_type
*Admin only.* Creates a new service/incident type.

- **API Parameters:**
    | Parameter | Type | Required | Description |
    |-----------|------|----------|-------------|
    | `#token` | string | Yes | An Admin session token. |
    | `name` | string | Yes | Name of the new service type. Must be non-empty. |

- **Return Values:**
    ```json
    {
        "rc": 0,
        "message": "success",
        "type_id": "abc123"
    }
    ```

    Returns the generated `type_id` for the newly created type.

- **Error Cases:**
    | rc | Message | Scenario |
    |----|---------|----------|
    | 103 | current user does not have privileges | The caller is not an Admin. |
    | 201 | invalid user token | Invalid or expired token. |

- **Usage & Flows:**
    Used by the admin in the management portal (SDS 5.4.1) to add new service/incident categories. Once added, the new type appears immediately in the New Call process for residents and officers.

## Endpoints — GPS & Tracking Settings

### POST Settings/get_gps_settings
*Admin only.* Retrieves the current GPS and tracking configuration.

- **API Parameters:**
    | Parameter | Type | Required | Description |
    |-----------|------|----------|-------------|
    | `#token` | string | Yes | An Admin session token. |

- **Return Values:**
    ```json
    {
        "rc": 0,
        "message": "success",
        "gps_interval_normal": 30,
        "gps_interval_emergency": 10,
        "gps_stale_threshold": 2,
        "location_history_retention": 90,
        "map_refresh_interval": 30,
        "patrol_compliance_threshold": 15,
        "emergency_eta_interval": 60,
        "map_provider": "google_maps"
    }
    ```

    | Field | Type | Description |
    |-------|------|-------------|
    | `gps_interval_normal` | integer | GPS transmission interval in seconds during normal patrol. |
    | `gps_interval_emergency` | integer | GPS transmission interval in seconds during emergency response. |
    | `gps_stale_threshold` | integer | Minutes without GPS update before an alert is triggered. |
    | `location_history_retention` | integer | Days to retain GPS history data. |
    | `map_refresh_interval` | integer | Portal map auto-refresh interval in seconds. |
    | `patrol_compliance_threshold` | integer | Minutes overdue at a waypoint before triggering a skip alert. |
    | `emergency_eta_interval` | integer | ETA recalculation interval in seconds during emergency. |
    | `map_provider` | string | Map provider identifier (e.g., `"google_maps"`). |

- **Error Cases:**
    | rc | Message | Scenario |
    |----|---------|----------|
    | 103 | current user does not have privileges | The caller is not an Admin. |
    | 201 | invalid user token | Invalid or expired token. |

- **Usage & Flows:**
    Used by the management portal to display the current GPS configuration on the Settings page (SDS 5.3). Values control officer app GPS transmission frequency, the Live Tracking map refresh rate (SDS 4.9.5), and ETA recalculation during emergency responses (SDS 2.4.1.2).

---

### POST Settings/update_gps_settings
*Admin only.* Updates GPS and tracking configuration. Only provided fields are changed; omitted fields retain their current value.

- **API Parameters:**
    | Parameter | Type | Required | Description |
    |-----------|------|----------|-------------|
    | `#token` | string | Yes | An Admin session token. |
    | `gps_interval_normal` | integer | No | GPS transmission interval in seconds during normal patrol. Range: 10–120. Default: 30. |
    | `gps_interval_emergency` | integer | No | GPS transmission interval in seconds during emergency. Range: 5–30. Default: 10. |
    | `gps_stale_threshold` | integer | No | Minutes without GPS update before alert. Default: 2. |
    | `location_history_retention` | integer | No | Days to retain GPS history. Default: 90. |
    | `map_refresh_interval` | integer | No | Portal map refresh interval in seconds. Default: 30. |
    | `patrol_compliance_threshold` | integer | No | Minutes overdue at waypoint before skip alert. Default: 15. |
    | `emergency_eta_interval` | integer | No | ETA recalculation interval in seconds. Default: 60. |
    | `map_provider` | string | No | Map provider identifier. Default: `"google_maps"`. |

- **Return Values:**
    ```json
    {
        "rc": 0,
        "message": "success"
    }
    ```

- **Error Cases:**
    | rc | Message | Scenario |
    |----|---------|----------|
    | 103 | current user does not have privileges | The caller is not an Admin. |
    | 201 | invalid user token | Invalid or expired token. |
    | 742 | gps_interval_normal out of range (must be 10-120) | `gps_interval_normal` value is outside the permitted 10–120 seconds range. |
    | 743 | gps_interval_emergency out of range (must be 5-30) | `gps_interval_emergency` value is outside the permitted 5–30 seconds range. |

- **Usage & Flows:**
    Used by the admin to configure GPS behaviour from the Settings page (SDS 5.3). Changes take effect immediately for officer apps and the Live Tracking portal view. Lower `gps_interval_emergency` values improve real-time tracking accuracy during emergencies but increase battery usage on officer devices.
