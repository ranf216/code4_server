# Incident Reports — UI Updates Required

**Module:** `Report` (Phase 7.2)  
**Applies to:** Web Admin Portal (React), Officer Mobile App (React Native), Resident Mobile App & Web Portal  
**Last Updated:** 2026-10-12  
**API reference:** `docs/library/report-app-developer-guide.md` · **Server spec:** `docs/modules/report-module-specification.md`

Every screen below is backed by an existing endpoint; the endpoint, parameters and response fields are named next to each UI element. Server-side rules (locking, visibility, validation) are enforced by the API — the UI mirrors them for usability but must always handle the corresponding error codes.

Brand/visual constants:

| Token | Value | Use |
|---|---|---|
| Accent (Code4 Navy) | `#003366` | Report titles, section headers, dividers, PDF preview chrome (template `accent_color` overrides it) |
| Watermark | `CONFIDENTIAL – AUTHORISED USE ONLY`, diagonal, 15% opacity | PDF / client preview |
| Footer | `Generated by Code4 Axis Security Operations` · delivery date/time · `Page X of Y` | PDF |

Status badge colours (suggested): `draft` grey · `submitted` blue · `under_review` amber · `changes_requested` red · `approved` green · `delivered` navy `#003366`.

## 1. Web Admin Portal

### 1.1 Reports Queue (`Incident Reports` menu)

**Data:** `Report/get_reports_list` (admin), 0-based `page`, 20 rows per page (server-controlled), `num_of_items` / `num_of_pages` for the pager.

**Tab bar** (maps to `statuses`):

| Tab | `statuses` |
|---|---|
| All | omitted (all non-draft reports) |
| Pending Review | `["submitted", "under_review"]` |
| Changes Requested | `["changes_requested"]` |
| Approved | `["approved"]` |
| Delivered | `["delivered"]` |

**Filter bar:**

| Control | Parameter |
|---|---|
| Community multi-select (hidden for community-scoped admins) | `community_ids` |
| Author (officer) multi-select | `officer_user_ids` |
| Submitted date range picker | `from_date`, `to_date` (admins filter by **submitted** date) |
| Category | `category` (`get_report_metadata.categories`) |
| Review required toggle (All / Yes / No) | `review_required` (omit for All) |
| Search box (title, report #, officer name) | `search_text` |
| Column sort (Submitted, Created, Status, Title, Report #) | `sort_by`, `sort_dir` |

**Table columns:** Report # (`report_id`) · Title · Community · Category · Officer (`officer_name`) · Status badge · Submitted (`submitted_on`) · Review indicator · Actions (Open).

**Review lock indicator** (from `review_lock`, `reviewer_name`):
- Lock icon + `Under review by <locked_by_name>` + countdown to `expires_on` (30-minute TTL; refreshes whenever the reviewer acts).
- When the current user holds the lock: `Reviewing (you) · mm:ss`.
- `under_review` with `is_locked: false`: `Review paused — <reviewer_name>` (can be taken over with **Start Review**).
- Countdown is display-only; re-fetch the list on expiry or every 60 s while visible.

**Empty states:** "No reports awaiting review" (Pending Review tab), "No reports match your filters".

### 1.2 Review Studio (report detail)

Opened from the queue. **Data:** `Report/get_report` (admin view). Split-screen layout:

```
┌──────────────────────────────── Report #128 · Incident - Oak Park - 10/12/2026 ── [Status badge] ─┐
│ LEFT (≈65%) — Report content                    │ RIGHT (≈35%) — Manager panel                  │
│  Header: community, officer, call #, POI #,     │  Review status + lock countdown               │
│          created / submitted dates               │  [Start Review] / [Release]                   │
│  Section cards (sort_order):                     │  Section visibility checklist                 │
│   ▸ title + "Client" toggle                      │  Management summary (≤1000)                   │
│   ▸ fields (value | original submitted value)    │  [Request Changes] [Approve] [Deliver]        │
│   ▸ attachments gallery                          │  Client preview / PDF panel                   │
│   ▸ Manager notes (internal, ≤2000)              │  History timeline (get_report_history)        │
└──────────────────────────────────────────────────┴───────────────────────────────────────────────┘
```

**Left pane — content**
- Render `sections[]` in `sort_order`; each `fields[]` entry by `field_type` (text, date, location with map pin, dropdown chips, file/signature thumbnails from `attachments[].url`).
- **Audit comparison:** when `submitted_value` differs from `value`, show the officer's original value struck-through with an "Edited by manager" tag.
- Fields with `is_locked: true` are always read-only (lock icon, tooltip "Auto-filled from the call / POI record").
- **Editing** is enabled only when `can_edit` is true (status `under_review` and the user is the reviewer). Save → `Report/update_report` with only the changed sections/fields. Handle `732` (locked), `731` (invalid value, `info` = field label), `736` (review lost → prompt to restart).
- **Manager notes** textarea per section (internal — badge "Internal · never shared with officer or client") → `update_report {report_section_id, manager_notes}`.

**Right pane — manager controls**

| Control | Visible when | Action |
|---|---|---|
| **Start Review** | `status` is `submitted`, or `under_review` with an expired lock | `Report/start_review`; on `727` show "Under review by `locked_by_name` until `expires_on`" |
| Lock keep-alive | user is reviewing | call `start_review` again every ~10 min while the studio is open (refreshes the 30-min lock) |
| **Release** / leaving the page | user is reviewing | `Report/release_review` (also on route change / tab close where possible) |
| **Section visibility checklist** | reviewing | one checkbox per section (`client_included`); toggle → `update_report {client_included}`; also sent as `included_section_ids` on approval |
| **Management summary** | reviewing | textarea, 1000-char counter; sent with Approve |
| **Request Changes** | reviewing | modal with **mandatory** comments (1–1000 chars, counter) → `Report/request_changes {comments}`; the officer sees them as the revision banner |
| **Approve Report** | reviewing | confirmation dialog listing included / excluded sections → `Report/approve_report {included_section_ids, management_summary}` |
| **Deliver to Client** | `status = approved` | confirmation ("The client will be notified and the report locked permanently") → `Report/deliver_report`; show spinner (PDF generation) and open the returned `pdf_url` |
| **Download PDF** | `status = delivered` | `Report/export_report_pdf` → open `pdf_url` |
| **Regenerate PDF** (super admin / manager) | `status = delivered` | `export_report_pdf {regenerate: true}`; logged in history |

**Client preview / PDF panel**
- Before delivery: render an in-browser **client preview** from the admin payload — only sections with `client_included: true`, no manager notes, no field configuration — styled with the accent colour, the management summary at the top, and a CSS diagonal watermark at 15% opacity. Label it "Preview — final PDF is generated on delivery".
- After delivery: embed the generated PDF (`pdf_url` from `export_report_pdf`; URLs are signed/time-limited — fetch a fresh one when opening the panel).

**History timeline** — `Report/get_report_history`: one entry per `history[]` item with `action_name`, `user_name`, `created_on`, `comment`; expandable field-level diffs from `changes` (`label: old_value → new_value`, attachments added/removed, `manager_notes` / `client_included` changes).

**Error handling:** `726` (report changed — reload), `713`/`714`/`728`/`729` (status changed — reload and show the new status), `730` n/a for admins, `742` (PDF before delivery), `103` (outside community scope).

### 1.3 Settings → Notifications

Add the toggle **"Report under review (notify officer)"** → `report_under_review_enabled` (`Settings/update_notification_settings`), next to the existing report toggles (`report_submitted_enabled`, `report_approved_enabled`, `report_changes_enabled`, `report_delivered_enabled`).

### 1.4 Notifications

Clicking `report_submitted` / other report notifications (`payload.entity_type = "report"`) opens the Review Studio for `payload.entity_id`.

## 2. Officer Mobile App

### 2.1 My Reports workspace

**Data:** `Report/get_reports_list` (officer — own reports, newest first; date filter = created date).

| Tab | `statuses` | Badge |
|---|---|---|
| Drafts | `["draft"]` | count |
| Changes Requested | `["changes_requested"]` | red count (action needed) |
| In Review | `["submitted", "under_review"]` | — |
| Completed | `["approved", "delivered"]` | — |

Row: title, community, created date, status badge, call # / POI chip. FAB **New Report**.

### 2.2 Creating a report

Entry points:

| Entry point | Call |
|---|---|
| **New Report** (standalone) | template picker (`ReportTemplate/get_templates_list`) → optional **Recipient** picker (resident of the community; empty = "All residents of the community") → `create_report {template_id, client_user_id}` |
| Call details → **Write Report** | `create_report {template_id, call_id}` (recipient = call creator automatically; no recipient picker) |
| POI details → **Report Encounter** | `create_report {template_id, poi_id, latitude, longitude, location_address}` using the device GPS (if unavailable, omit coordinates — the server uses the last tracked position) |

Handle `711` (template no longer available), `735` / `741` (call / POI not accessible), `740` (recipient invalid), `500` (no community assigned).

### 2.3 Incident Form Wizard

**Data:** `Report/get_report` (officer view) → render one wizard step per section (`sort_order`); step indicator shows required sections with an asterisk (`is_required`).

| Field state | UI |
|---|---|
| `is_locked: true` | read-only with lock icon + caption "Auto-filled from call / POI" |
| `is_auto_populated: true`, `is_locked: false` (description, officer comments, media) | pre-filled, editable, caption "Pre-filled — you can edit" |
| `is_required: true` | asterisk; validated client-side before submit |
| `text` | multiline input with counter (`config.max_chars`, default 10,000) |
| `date` | date picker (`YYYY-MM-DD`) |
| `location` | address input + "Use my location" + map pin |
| `dropdown` | single / multi select from `config.dropdown_values` (`config.is_multi_select`) |
| `file_upload` | camera / gallery picker, thumbnails, remove button, counter `n / config.max_files` |
| `digital_signature` | signature pad (1 file) |

- **Save draft** (auto-save on step change) → `update_report` with changed sections; files: upload first, then send `{attachment_ids: <kept>, file_ids: <new>}`.
- **Submit** → `submit_report`; on `730` jump to the first entry of `missing_fields` and highlight all of them.
- After submit: toast by returned `status` — `submitted` "Sent for review", `approved` "Report approved (no review required)", `under_review` "Returned to <manager> for review".
- Editable only while `can_edit` is true; otherwise the wizard opens read-only (e.g. In Review / Completed). Handle `726` (status changed meanwhile — reload read-only).

### 2.4 Revision Feedback Banner

For `status = changes_requested`:
- Prominent red banner at the top of the report: **"Changes requested"** + `changes_comment` (full text, expandable).
- Primary action **Resubmit**: saves pending edits (`update_report`) then calls `submit_report` (the report returns directly to the requesting manager).
- Manager notes are never shown to officers.

### 2.5 Notifications

| Type | Officer UI |
|---|---|
| `report_under_review` | info toast "Report #N is being reviewed by <manager>" |
| `report_changes_requested` | high-priority notification → opens the report with the revision banner |
| `report_approved` / `report_delivered` | info notification → opens the read-only report |

### 2.6 POI detail screen

Under **Related Incidents**, list `related_incidents` (calls → Call Details) and `related_reports` (`Poi/get_poi_record`: title, status badge, created date → Report detail). Officers only receive their own linked reports.

## 3. Resident Mobile App & Web Portal

### 3.1 Delivered Reports Library (`Reports` menu)

**Data:** `Report/get_reports_list` (resident) — delivered reports addressed to the resident plus community-wide reports of their community, newest delivered first; date filter = delivered date.

| Column / element | Field |
|---|---|
| Title | `title` |
| Site | `community_name` |
| Date of incident report | `created_on` |
| Delivered on | `delivered_on` |
| Category | `category_name` |
| Actions | View · Download PDF |

Filters: category, delivered date range, search by title. Calls screen: "Reports for this call" link → `get_reports_list {call_id}`.

### 3.2 Client Report View

**Data:** `Report/get_report_for_client`.
- Header: title, site, officer, delivered date, category; accent colour `#003366`.
- **Management summary** card at the top (when present).
- Client-included sections only, read-only; attachments as an image gallery / file list. Internal sections, manager notes and field configuration are never returned by the API.
- Errors: `710` → "This report is no longer available".

### 3.3 Watermarked PDF Download

Button **Download PDF** (list and detail) → `Report/export_report_pdf {report_id}` → open / share / print `pdf_url` (signed and time-limited — always request a fresh URL). The PDF carries the diagonal `CONFIDENTIAL – AUTHORISED USE ONLY` watermark, the header (community, title, report ID) and the footer (delivery date/time, "Generated by Code4 Axis Security Operations", page X of Y).

### 3.4 Notifications

`new_incident_report` ("Incident report #N filed by <officer>") → opens the Client Report View. Community-wide reports (no specific recipient) do **not** trigger a notification — they appear in the library only.

## 5. Brief Items Not Available / Adjusted

| Brief item | Status |
|---|---|
| Live PDF preview before delivery | Client preview rendered in the browser from the admin payload (§1.2); the server-generated PDF exists from delivery onward |
| Request Changes "manager notes" | The modal sends `comments` (shown to the officer). Section **manager notes** are a separate, internal-only field |
| Admin authoring/submitting reports | Not supported — only officers create and submit reports (SDS) |
| Multi-manager collaborative review | Not supported — single reviewer with a 30-minute lock (Q6/Q7) |
